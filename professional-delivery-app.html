Delivery App

Teslim Uygulaması · C# WPF desktop app · runs the three tools
00Delivery App 01Delivery Sets 02Drawing List (TML) 03Room List (ID-RML)

The three tools made a full delivery possible in hours, but only for someone who could drive PowerShell. Teslim Uygulaması ("delivery app") puts the whole delivery into nine pages anyone in the team can follow: choose the project, scope, names, delivery details, then scan, fix, bind + PDF, lists and submit. A trial mode runs every step without writing a single project file.

From Service to Product

The last full delivery was done with the scripts and Claude, by me: about 18 active hours for work estimated at around 315 hours by hand. That made the next problem obvious. The speed lived in one person who knew which function to call in which order. The app takes that order, the office rules and the safety checks, and turns them into pages the team can click through. It runs the same PowerShell modules underneath, so the rules stay in one place and a fix to a tool is a fix to the app.

  • 2 OctFirst plan of the app; bind + PDF core tested on a single set.

Designed for the Person Using It

  • Pages open in order. Only "Proje seç" is open at first; each later page opens when the one before it is finished.
  • Nothing hidden below the fold. The next-step buttons are pinned to the bottom of the window; no page scrolls sideways at 1280×860 or 900×600.
  • Missing answers are named, not just blocked. An amber dot on the page, and a line beside the button: "Eksik: antet adı dili (Adlar) · PDF seçimi", each item a link to its page.
  • Plain Turkish, no step numbers in the text. Messages name the page ("Düzelt adımında") and use words for the modules' codes.
  • Trial mode first. Every step runs and every output appears, in a local work folder. The real project is read only.
  • Confirm, back up, then write. Every changed file is copied to the run folder before a change; protected sets are never written; no drawing is saved while one of its xrefs is not loaded.

How It Is Built

A WPF app (C#, .NET Framework 4.8, so it runs on every office PC without an installer) hosts the three PowerShell modules in its own runspace and calls their functions directly. Those generate AutoLISP and run AutoCAD headless through accoreconsole, several drawings at a time. The office rules live in one JSON file next to the app; project names and settings live in a shared folder, together with a scan cache that several computers can use. Every version is tested headless and with the real window drawn off-screen at two sizes on three projects, then installed with a verified backup and a written way back.
