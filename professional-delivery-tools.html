Delivery Sets

Automation tool 01 · PowerShell + AutoLISP
00Delivery App 01Delivery Sets 02Drawing List (TML) 03Room List (ID-RML)

A batch tool that keeps hundreds of AutoCAD delivery sets consistent: which base drawings each sheet references, how files, layouts and xrefs are named, title block date and revision, draw order, and bound, xref-free copies with PDFs for issue. It runs headless through AutoCAD's console, so a re-issue that kept a team of 10 busy for a full day now takes about half an hour.

The Problem

On large projects every sheet is its own drawing that overlays a stack of base drawings (plan, structure, facade, rooms, dimensions, doors, FFE …) plus a sheet border. Each package needs a different stack, and over months of revisions sets drift: a missing xref here, a duplicate there, an old border, a layout still named after a copied file. Before every issue someone opened hundreds of drawings by hand to check them, update the title block, bind a clean copy and plot it, which was slow and easy to get wrong under deadline pressure.

Rules Taught Once

The office's delivery rules used to live in people's heads. They are now written in one config and checked automatically on every set, so the next delivery starts from them instead of from memory.

  • Xrefs as overlay; every package gets its own list of base drawings.
  • Draw order: doors above plan and facade; where a package needs it, the room xref above all others.
  • Linetype scale 0.1 in the sets, 20 in the base drawings.
  • Layout name equal to the file name.
  • Title block date and revision per issue; English and Turkish sheet names from the drawing list, fitted to the line.
  • Legends at a fixed point on ceiling and floor plans; interior FFE sets open with a legend page.
  • Door wipeouts sent to the back before every bind, so no door looks broken on the sheet.
  • Output: bound copy in a dated DWG folder, PDF at sheet size, 1:1, office plot style.
  • Submission folder by building and package, with one current copy of the drawing list and the room list.
  • Drawing list: every delivered sheet in it, in the fixed package order.

How It Works

A PowerShell module reads the rules, generates AutoLISP scripts and runs them through accoreconsole, with no AutoCAD window, several drawings at a time. It reports first, writes a fix plan a person can read, and only then applies it. For the issue it binds every set into a clean copy, freezes the sheet name fields so they do not turn into "Model", plots each title block layout to a PDF at the size of its sheet border and copies the result into the submission folder.

Config→ Xref report→ Fix plan→ Review→ Apply→ Title block→ Bind + PDF→ Submission folder

Designed to Be Safe

Nothing changes until a human has read the plan. Drawings open in AutoCAD are skipped, a drawing whose report is incomplete is never planned, and bound copies are written only when every xref bound cleanly. The source sets always stay unbound and unsaved; existing outputs are kept unless a run is told to replace them, and the plot setting AutoCAD keeps outside the drawing is restored after every PDF run.

Results

Measured on a real re-issue of about 330 sheets over a network share, 4 parallel processes: title block update ≈ 7.5 min, bind and save ≈ 10 min, checking the few failures ≈ 10 min, roughly half an hour in total for work that used to take a team of 10 people a full day.

On the last full delivery (15 buildings) the tool checked every set against the rules, bound 385 sets and plotted 224 PDF sheets; AutoCAD opened drawings about 28,000 times to check, fix, bind or plot, with nobody clicking. Before the issue it caught 341 title blocks with the wrong date, 33 room xrefs drawn under the others, 12 door drawings with wipeouts in front of the doors, about 12 drawings that would not bind and 3 damaged files. The Excel rules and status workbooks give the team one shared view of what every package should contain and where each set stands.
